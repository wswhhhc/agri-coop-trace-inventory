# 前端 UI 增量实施计划

## 目标

将现有已打通业务功能改造成“现代农业数字化运营平台”风格：自然可信、数据优先、清晰克制，并支持浅色、深色、自动三种主题模式。

## 总体设计决策

- 风格：现代自然主义 + 企业数据中台，不使用土味农业装饰，也不使用过度炫技的大屏风格。
- 主色：农业绿 `#176B4D`；深色品牌绿 `#0F4C3A`；米白背景 `#F5F8F3`；稻穗金 `#C99A3D`。
- 语义色：正常绿、预警橙、严重红、信息蓝；状态不能只依靠颜色，还要有文字或图标。
- 浅色主题：米白页面背景、白色内容面板、深墨绿文字、轻边框和轻阴影。
- 深色主题：深墨绿背景、层次化深绿面板、降低饱和度的品牌色；不使用纯黑反转。
- 自动主题：默认跟随系统 `prefers-color-scheme`；用户手动选择后保存本地并覆盖系统设置。
- 字体：优先使用系统中文无衬线字体；数字列使用等宽数字，正文保持 14–16px 和 1.5 以上行高。
- 间距：统一 4/8px 间距体系；桌面页面控制最大内容宽度，移动端不出现横向滚动。
- 交互：按钮、表单、表格、抽屉、加载、错误、空状态统一；异步操作有禁用、进度和成功/失败反馈。
- 无障碍：键盘焦点、可读对比度、表单标签、图片替代文本、`prefers-reduced-motion` 均纳入验收。

## 增量原则

- 每个 UI 切片只改一个明确层级或一个业务页面组。
- 每个切片完成后运行聚焦测试、`pnpm build` 和 `git diff --check`，确认后用中文提交。
- 不在早期一次性重写所有页面；先建立公共基础，再让业务页面逐组复用。
- 不为了视觉效果改动 API、权限和业务状态逻辑。
- 页面样式先保证桌面端可读，再补 375px、768px、1440px 三档响应式验证。

## 阶段一：设计基础

- [x] UI01 设计令牌与主题变量：建立颜色、字体、间距、圆角、阴影、层级和动效变量。
- [ ] UI02 浅色/深色/自动主题切换：实现主题状态、系统监听、用户选择持久化和首屏防闪烁。
- [ ] UI03 全局基础样式：统一页面背景、正文、链接、滚动条、焦点环、按钮和原生表单控件。

检查点 A：三种主题可以切换；颜色均通过语义变量使用；现有测试和构建不回归。

## 阶段二：应用框架与公共组件

- [ ] UI04 现代化 AppShell：改造侧栏、顶部栏、内容区、面包屑和移动端导航结构。
- [ ] UI05 公共页面组件：统一 PageHeader、PageState、空状态、错误状态、加载骨架和权限提示。
- [ ] UI06 数据组件：统一卡片、指标卡、状态徽章、筛选栏、表格、分页和详情抽屉。
- [ ] UI07 反馈组件：统一 Toast、确认弹窗、操作进度、异步任务状态和表单错误提示。

检查点 B：任意一个旧页面套用公共组件后，三种主题、焦点状态和移动端布局均正常。

## 阶段三：首页与核心运营模块

- [ ] UI08 首页看板：指标卡、库存趋势、预警分布、出库排行和预测对比，突出风险优先级。
- [ ] UI09 库存管理：库存风险表格、筛选区、详情抽屉和入库/出库等操作入口。
- [ ] UI10 库存操作表单：入库、出库、盘点、报损、调拨表单统一布局和反馈。
- [ ] UI11 预警中心：待处理优先、严重程度层级、预警详情和处理操作。

检查点 C：用户进入系统后能快速看懂当前风险，并完成一次库存操作和一次预警处理。

## 阶段四：追溯与质量业务

- [ ] UI12 批次列表与筛选：强化批次状态、临期提示、追溯入口和表格密度。
- [ ] UI13 批次详情：批次信息、二维码、公开追溯入口、质检卡片和时间线。
- [ ] UI14 质检与附件：质检表单、项目分组、附件列表、上传进度和关联状态。
- [ ] UI15 公开追溯页：独立的可信展示风格，适配手机扫码访问。

检查点 D：从批次列表可以进入详情、查看质量和时间线，并能打开公开追溯页面。

## 阶段五：AI 与基础资料

- [ ] UI16 AI 预测页面：模型版本、训练任务、预测任务和结果详情分区展示。
- [ ] UI17 预测结果可视化：趋势线、预测区间、库存对比、建议补货和限制说明。
- [ ] UI18 产品与分类：产品、分类、启停状态和编辑表单统一视觉。
- [ ] UI19 合作社、仓库、用户：组织管理、权限范围、授权和密码操作统一视觉。
- [ ] UI20 角色权限：权限分组、角色详情和授权操作的高可读性布局。

检查点 E：复杂页面中的任务状态、权限状态和业务数据不会互相混淆。

## 阶段六：导出、审计与质量收尾

- [ ] UI21 报表导出：筛选条件、任务进度、成功下载和失败恢复。
- [ ] UI22 审计日志：高密度筛选表格、结果徽章、详情 JSON 和敏感信息边界。
- [ ] UI23 响应式与无障碍复查：375px、768px、1440px、键盘导航、对比度和减少动效。
- [ ] UI24 性能与体验复查：路由懒加载、骨架屏、图片尺寸、布局抖动和重复样式清理。
- [ ] UI25 全量验证与最终提交：测试、构建、视觉走查、占位检查和最终中文 Git 提交。

检查点 F：所有业务页面统一主题、统一组件、无视觉占位、无明显响应式和无障碍问题。

## 每个切片的固定验收模板

1. 明确本切片改动的组件和页面范围。
2. 先补或调整组件测试，再实现样式和交互。
3. 验证浅色、深色、自动三种模式。
4. 验证加载、空数据、错误、禁用、成功和权限状态。
5. 验证 375px、768px、1440px 至少三种宽度。
6. 运行 `pnpm exec vitest run`、`pnpm build`、`git diff --check`。
7. 更新进度文档并使用中文提交说明。

## 明确不做

- 不先制作独立营销官网或复杂首页动效。
- 不使用 emoji 作为功能图标。
- 不用大量渐变、玻璃拟态或农业插画掩盖数据层级。
- 不在 UI 阶段修改后端业务接口和权限语义。
