# 农业合作社追溯与库存预警系统开发计划

## 总体策略

采用“最小公共底座 + 业务模块纵向闭环”的混合方式。公共代码只实现已经被第一个业务切片验证需要的能力，避免一次性建设大量未使用的抽象。

## 依赖顺序

数据库迁移/配置 → ORM模型与仓储 → 认证与权限 → 组织/产品/批次 → 库存事务 → 追溯 → 预警 → AI预测 → 报表审计。

## 阶段与检查点

### 阶段1：最小底座

- 配置管理、日志、数据库异步会话、事务依赖、统一响应模型。
- 基础异常类型与全局异常处理。
- SQLAlchemy 基础模型、UUID/时间字段、分页参数、测试数据库夹具。
- 验收：应用可启动；数据库连接和事务测试通过；异常响应与接口文档一致。

### 阶段2：身份认证与权限闭环

- 用户、角色、权限模型；登录、刷新令牌、当前用户。
- 合作社/仓库数据范围依赖。
- 验收：三种后台角色权限和数据范围测试通过，越权返回约定状态码。

### 阶段3：组织、产品、批次与质检

- 合作社、仓库、人员、产品分类、产品、批次、质检。
- 验收：可以创建批次、录入质检并生成追溯码；权限边界有效。

### 阶段4：库存事务闭环

- 当前库存、库存操作头、库存流水；入库、出库、盘点、报损，随后实现调拨。
- 幂等、并发锁定、事务回滚和 Redis 缓存失效。
- 验收：库存与流水一致，不出现负库存，重复请求不重复扣减。

### 阶段5：追溯与规则预警

- 内部/公开追溯、二维码、临期/缺货/积压/质检异常预警。
- 验收：公开接口脱敏且限流；预警生成、处理和审计链路完整。

### 阶段6：AI、报表与审计

- 任务记录、模型版本、预测结果、异步训练/预测、统计大屏、Excel 导出、审计查询。
- 验收：异步任务可查询；预测标记合成数据；报表和审计受数据权限约束。

## 重要原则

- 不先编写“所有公共工具”；每个工具必须有业务调用方和测试。
- 每完成一个阶段，先运行聚焦测试，再进入下一个阶段。
- 数据库模型可按依赖批量建立，但接口、服务和测试必须按业务切片闭环。
