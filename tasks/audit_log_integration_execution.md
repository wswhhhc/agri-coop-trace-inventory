# 后端关键业务审计补全执行书

## 目标

补齐 P0 要求的关键业务审计写入：批次操作、库存入库/出库/调拨/盘点/报损，以及权限相关的关键管理操作；保持现有审计查询、脱敏、独立事务和统一错误契约不变。

## 范围

- 只修改后端代码、后端测试和本执行书。
- 不建设前端，不修改数据库表结构，不新增不必要的公共抽象。
- 复用现有 `AuditEvent`、`AuditLogService` 和审计脱敏机制。
- 审计失败不得回滚已经成功的批次或库存主业务；审计失败只记录服务端日志。
- 测试数据库连接直接使用项目 `backend/.env`，不在代码、文档或提交中复制密码。

## 既有约束

- Service/Repository 事务边界保持不变。
- 审计写入使用独立 Session/事务。
- 审计详情不得出现密码、Token、Cookie 等敏感字段。
- 库存幂等重放不得重复产生库存变更；审计应能区分首次成功和重复请求结果。
- 所有 Git 提交说明使用中文。

## 验收标准

1. 批次创建、批次修改和状态变更均有成功/失败审计记录。
2. 五类库存写操作均有成功/失败审计记录；库存事务失败不产生成功日志。
3. 幂等重复请求不会重复改变库存，审计结果可识别重复请求。
4. 审计日志包含操作者、时间、对象、动作、结果和请求 ID。
5. 审计详情不包含密码、Token、Cookie 等敏感信息。
6. 审计持久化失败不影响已成功的批次/库存主业务。
7. 现有全量测试、mypy、Ruff 和严格门禁继续通过。
